### Faster date-window lookups, and a paged event feed (#2391)

- **Events in a date window** (`Event::occurringBetween()` with both ends, behind the home page, the day and week views and the calendar feed): the query read every event to find the ones in the window. It now narrows by `last_start_at` first, which is indexed. On a copy of the production numbers a week from today went from 58 ms and 18,000 rows examined to 1 ms and 150; on dev the home page went from 66 to 21 ms of SQL and `/events/week` from 43 to 3 ms. Old and new return the same events for 1,812 windows tried against production data. It relies on `last_start_at` never being empty or before `start_at`: true of all 20,402 production events, and kept so by the model on every save.
- **Event feed** (`/events/feed`): was 1,000 events of every date on one page, 5 MB and over four seconds. It now starts from today, soonest first, 100 to a page with Previous and Next links (107 KB, about 0.1 s on dev). A date filter, in the request or saved from the events list, still reaches past events; a filter without dates narrows the feed and leaves it starting today. `/events/feed/tag/{tag}` pages at 100 as well.
